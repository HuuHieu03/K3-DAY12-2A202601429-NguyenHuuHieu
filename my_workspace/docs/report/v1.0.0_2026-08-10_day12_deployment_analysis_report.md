# Báo Cáo Tổng Hợp - Day 12 Deployment Lab

## 1. Tổng Quan Dự Án

Bài lab này hướng dẫn biến một AI agent chạy trên localhost thành một dịch vụ production-ready có thể deploy lên cloud. Trọng tâm không chỉ là làm cho hệ thống chạy được, mà là làm cho nó phù hợp với môi trường production: có cấu hình rõ ràng, container hóa, deploy cloud, bảo mật, khả năng mở rộng và độ tin cậy cao.

## 2. Goals Của Bài Lab

- Hiểu vì sao môi trường development và production khác nhau.
- Biết cách chuẩn hóa config, secrets và health check theo 12-factor app.
- Containerize agent bằng Docker và tối ưu image theo multi-stage build.
- Deploy lên cloud bằng Railway, Render hoặc Cloud Run.
- Bảo vệ API bằng authentication, rate limiting và cost guard.
- Thiết kế hệ thống có thể scale ngang và vận hành ổn định.
- Hoàn thành final project production-ready trong `06-lab-complete`.

## 3. Cần Nắm Những Gì

### 3.1 Dev vs Production

- Không hardcode secrets.
- Dùng environment variables cho config.
- Có health/readiness check.
- Có graceful shutdown để không mất request.

### 3.2 Docker Và Containerization

- Hiểu Dockerfile, image, container, port mapping.
- Biết vì sao copy `requirements.txt` trước rồi mới copy source.
- Hiểu lợi ích của multi-stage build và `.dockerignore`.
- Biết dùng Docker Compose để chạy multi-service stack.

### 3.3 Cloud Deployment

- Phân biệt Railway, Render và Cloud Run.
- Hiểu deploy flow, env vars trên cloud và public URL.
- Nắm được khái niệm cold start và khi nào nên chọn platform nào.

### 3.4 Security

- Phân biệt API Key, JWT, và lớp bảo vệ trước agent.
- Hiểu rate limiting để chặn abuse.
- Hiểu cost guard để bảo vệ ngân sách.

### 3.5 Scaling & Reliability

- Hiểu liveness probe và readiness probe.
- Biết vì sao stateless quan trọng khi scale.
- Hiểu Redis dùng để chia sẻ session giữa nhiều instance.
- Nắm vai trò của Nginx/load balancer trong phân phối traffic.

## 4. Cần Hiểu Được Gì

- Một agent production-ready không chỉ chạy được, mà còn phải deploy được, quan sát được, bảo vệ được và mở rộng được.
- Các lỗi phổ biến của localhost app thường đến từ hardcode config, thiếu health check, thiếu shutdown an toàn, và lưu state trong memory.
- Docker và cloud không phải mục tiêu cuối; chúng là phương tiện để đảm bảo tính nhất quán, khả năng vận hành và khả năng mở rộng.
- Bảo mật và kiểm soát chi phí là yêu cầu bắt buộc khi agent có thể được public ra internet.

## 5. Các Bước Thực Hiện Bài Lab

### Bước 0: Chuẩn Bị

#### Kiến thức cần nắm (Chi tiết)
- **pydantic‑settings**: cách khai báo class Settings, ánh xạ env vars, không có giá trị default cho secret.
- **Cấu hình 12‑Factor**: tách config ra .env, không hardcode.
- **Health check**: endpoint `/health` trả về JSON đơn giản, không phụ thuộc vào dependencies.
- **Graceful shutdown**: xử lý SIGTERM, set flag `shutting_down`.
- **Redis cơ bản**: dùng `fakeredis` khi chưa có Docker.

- Đọc nhanh `README.md`, `LAB_GUIDE.md`, `DEPLOYMENT.md` để nắm bức tranh tổng thể và môi trường cần có.

### Bước 1: Localhost vs Production

#### Kiến thức cần nắm (Chi tiết)
- **12‑Factor Config**: sử dụng `app/config.py` với `Settings`.
- **Health vs Ready**: `/health` liveness, `/ready` readiness (Redis). 
- **Graceful shutdown** trong `app/lifecycle.py`.
- **Logging JSON**: `app/logging_utils.py` xuất log dạng JSON.
- **API key auth**: header `X‑API‑Key`, so sánh bằng `secrets.compare_digest`.

- Mở `01-localhost-vs-production/develop/app.py` để tìm anti-patterns.
- Chạy bản basic để thấy nó hoạt động nhưng chưa production-ready.
- So sánh với bản `production/` để hiểu env vars, health check và graceful shutdown.

### Bước 2: Docker Containerization

#### Kiến thức cần nắm (Chi tiết)
- **Docker multi‑stage**: builder & runtime stage, giảm kích thước, copy `requirements.txt` trước.
- **`.dockerignore`**: loại bỏ `.env`, `__pycache__`, `.venv`.
- **User non‑root**: `RUN useradd --uid 10001 appuser` và `USER appuser`.
- **Healthcheck** trong Dockerfile.
- **Docker Compose**: service `agent` phụ thuộc `redis`.

- Đọc Dockerfile ở `02-docker/develop`.
- Build và run image basic.
- So sánh với `02-docker/production` để hiểu multi-stage build và Docker Compose stack.

### Bước 3: Cloud Deployment

#### Kiến thức cần nắm (Chi tiết)
- **Railway / Render**: cấu hình `railway.toml` hoặc `render.yaml`, set env vars.
- **Public URL**: nhận từ platform, ghi vào `DEPLOYMENT.md`.
- **Cold start**: ảnh hưởng latency, tối ưu bằng image nhẹ.
- **ENV `PORT`**: đọc từ biến môi trường.

- Chọn Railway/Render/Cloud Run theo mục tiêu học tập.
- Deploy bản cloud trong `03-cloud-deployment`.
- Kiểm tra public URL và env vars trên platform.

### Bước 4: API Gateway & Security

#### Kiến thức cần nắm (Chi tiết)
- **API Key authentication** trong `app/auth.py`.
- **Rate limiting sliding‑window** với Redis Sorted Set.
- **Cost guard**: tính chi phí USD, ngăn vượt ngân sách.
- **JWT (optional)**: nếu triển khai production version.
- **Security headers** và CORS.

- Chạy bản basic ở `04-api-gateway/develop`.
- Kiểm tra authentication bằng API key.
- Sang bản production để hiểu JWT, rate limiting và cost guard.

### Bước 5: Scaling & Reliability

#### Kiến thức cần nắm (Chi tiết)
- **Liveness vs Readiness** probes.
- **Graceful shutdown** khi SIGTERM.
- **Stateless design**: dùng Redis để lưu lịch sử hội thoại.
- **Nginx load balancer** cấu hình `nginx/nginx.conf`.
- **Horizontal scaling**: chạy đa instance với Docker Compose `--scale agent=3`.

- Kiểm tra health/readiness và graceful shutdown ở `05-scaling-reliability/develop`.
- Chạy bản production với Redis + Nginx để hiểu stateless design.
- Test nhiều instance để thấy session vẫn giữ được qua Redis.

### Bước 6: Final Project

#### Kiến thức cần nắm (Chi tiết)
- **Tích hợp toàn bộ** các khối: config, Docker, cloud, security, scaling.
- **Checklist production‑ready**: health, ready, auth, rate limit, cost guard, shutdown.
- **Deliverables**: `MISSION_ANSWERS.md`, `DEPLOYMENT.md`, screenshots.
- **Testing**: chạy toàn bộ checkpoint test.

- Hoàn thiện `06-lab-complete`.
- Chạy checklist production readiness.
- Chuẩn bị `MISSION_ANSWERS.md`, `DEPLOYMENT.md` và screenshot theo checklist bàn giao.

## 6. Kết Luận Ngắn

Bài lab này là một lộ trình đầy đủ từ local app đến production service. Nếu đi đúng thứ tự, người học sẽ hiểu được toàn bộ chuỗi kỹ năng cần có để triển khai một AI agent thật sự sẵn sàng cho môi trường production.
