## 1. Mục Tiêu Tổng Quan & Ý Nghĩa
Mục tiêu cốt lõi của bài lab là đưa một dịch vụ AI Agent viết bằng FastAPI đang chạy ở localhost lên một môi trường cloud thực tế (production-ready). Dịch vụ này phải đảm bảo các tiêu chí nghiêm ngặt về:
- **Cấu hình chuẩn hóa (12-Factor App)**: Tách biệt hoàn toàn cấu hình khỏi mã nguồn.
- **Tối ưu hóa Containerization**: Dockerfile multi-stage bảo mật, giảm kích thước image và chạy dưới quyền user thường.
- **Bảo mật API**: Bảo vệ tài nguyên tính toán thông qua API Key, rate limit, và cost guard.
- **Độ tin cậy & Khả năng mở rộng**: Readiness/liveness probes, stateless design qua Redis, và graceful shutdown để không làm rớt request khi cập nhật hoặc scale ngang.

## 2. Phân Tích Chi Tiết Các Checkpoint Thực Hành (CP0 - CP5)

### 🔴 Checkpoint 0: Setup Môi Trường
- **Mục tiêu**: Chuẩn bị môi trường Python 3.11+, cài đặt thư viện từ `requirements.txt`, thiết lập file `.env` chứa `AGENT_API_KEY` (bí mật, không commit) và chạy kiểm thử ban đầu.
- **Lệnh chạy**: `pytest tests/ -v -m "not docker"` (mong đợi rớt hầu hết do chưa viết code).

### 🔴 Checkpoint 1: 12-Factor Config, Health Check & Logging
- **File cần chỉnh sửa**: `app/config.py`, `app/logging_utils.py`, `app/main.py`.
- **Yêu cầu & Kiến thức chi tiết**:
  - **12-Factor Config (`pydantic-settings`)**: Sử dụng class `Settings` kế thừa từ `BaseSettings`. Các cấu hình nhạy cảm như `agent_api_key` **bắt buộc không được cung cấp giá trị mặc định** để tránh rủi ro bảo mật và ép hệ thống phải báo lỗi sớm (fail-fast) nếu quên cấu hình.
  - **Health Check `/health`**: Dùng để kiểm tra liveness (process có hoạt động không). Endpoint này chỉ trả về trạng thái của process FastAPI và **không** kết nối tới các dịch vụ ngoài (Redis, DB) nhằm tránh hiện tượng sập dây chuyền (cascading failures).
  - **Logging JSON**: Ghi log ra stdout dưới dạng JSON trên một dòng duy nhất (single line, không indent). Điều này giúp các hệ thống thu thập log tập trung (như Loki, Datadog) dễ dàng phân tích và truy vấn.
- **Lệnh chạy**: `pytest tests/test_cp1.py -v`.

### 🔴 Checkpoint 2: Docker Containerization
- **File cần chỉnh sửa**: `Dockerfile`, `docker-compose.yml`, `.dockerignore`.
- **Yêu cầu & Kiến thức chi tiết**:
  - **Multi-stage Build**: Chia Dockerfile làm hai giai đoạn (`builder` và `runtime`). Stage builder chịu trách nhiệm cài đặt và biên dịch thư viện, sau đó chỉ copy kết quả biên dịch sang stage runtime. Giúp giảm dung lượng image xuống dưới 500MB.
  - **Caching Layer**: Đặt `COPY requirements.txt .` và `RUN pip install...` lên trước khi copy source code (`COPY app/ ./app`). Nhờ đó, thay đổi code không làm Docker cài lại toàn bộ thư viện.
  - **Non-root User**: Chạy container bằng user thường (`USER appuser`) thay vì `root` để giảm thiểu rủi ro leo thang đặc quyền nếu ứng dụng bị tấn công.
  - **Docker Compose**: Định nghĩa cụm dịch vụ gồm `agent` và `redis`. Agent kết nối tới Redis qua tên service làm hostname (`redis://redis:6379/0`).
- **Lệnh chạy**: `pytest tests/test_cp2.py -v`.

### 🔴 Checkpoint 3: API Security
- **File cần chỉnh sửa**: `app/auth.py`, `app/rate_limiter.py`, `app/cost_guard.py`, `app/main.py`.
- **Yêu cầu & Kiến thức chi tiết**:
  - **Authentication**: Xác thực API key thông qua header `X-API-Key`. So sánh khóa bằng hàm an toàn thời gian `secrets.compare_digest` để chống tấn công phân tích thời gian (timing attacks).
  - **Rate Limiting**: Triển khai thuật toán cửa sổ trượt (sliding window) 60 giây bằng Redis Sorted Set (ZSET). ZSET lưu timestamp của các request và tự động dọn dẹp các bản ghi cũ bằng `zremrangebyscore`.
  - **Cost Guard**: Kiểm soát chi phí bằng cách lưu tổng chi tiêu của người dùng theo tháng với key định dạng `cost:<user>:<YYYY-MM>`. Chặn request bằng mã lỗi 403 (hoặc 402) nếu tổng chi tiêu vượt quá hạn mức cấu hình (`MONTHLY_BUDGET_USD`).
- **Lệnh chạy**: `pytest tests/test_cp3.py -v`.

### 🔴 Checkpoint 4: Scaling & Reliability
- **File cần chỉnh sửa**: `app/store.py`, `app/lifecycle.py`, `app/main.py`.
- **Yêu cầu & Kiến thức chi tiết**:
  - **Stateless Session Store**: Chuyển toàn bộ lịch sử hội thoại của người dùng từ bộ nhớ RAM sang Redis bằng lệnh `rpush` và giới hạn độ dài bằng `ltrim` để tránh rác bộ nhớ. Thiết kế stateless giúp hệ thống có thể mở rộng (scale ngang) ra nhiều instance mà không lo mất đồng bộ session.
  - **Readiness Probe `/ready`**: Khác với `/health`, endpoint này chỉ trả về HTTP 200 khi kết nối tới Redis thành công. Khi Redis mất kết nối, `/ready` trả về 503 để load balancer tạm thời rút instance ra khỏi vòng xoay traffic mà không cần restart container.
  - **Graceful Shutdown**: Đăng ký handler xử lý tín hiệu `SIGTERM` và `SIGINT`. Khi nhận được tín hiệu tắt app, ứng dụng sẽ chuyển flag `shutting_down = True` (khiến `/health` và `/ready` trả về 503 để load balancer ngừng gửi traffic mới), uvicorn sẽ xử lý nốt các request dở dang rồi mới dừng hoàn toàn.
- **Lệnh chạy**: `pytest tests/test_cp4.py -v`.

### 🔴 Checkpoint 5: Cloud Deployment
- **File cần chỉnh sửa**: `DEPLOYMENT.md`, `screenshots/`, `railway.toml` / `render.yaml`.
- **Yêu cầu & Kiến thức chi tiết**:
  - Thực hiện deploy ứng dụng lên các nền tảng Cloud (Railway hoặc Render).
  - Thiết lập đầy đủ các biến môi trường cấu hình trên dashboard của platform.
  - Điền đầy đủ thông tin vào [DEPLOYMENT.md](file:///d:/tai%20lieu%20hoc%20tap/VinAI/Day12/Lap/K3-Day12-Cloud-Services-And-Deployment/DEPLOYMENT.md) gồm Public URL, Platform, danh sách biến môi trường đã set (không ghi giá trị API key) và dán kết quả test curl.
- **Lệnh chạy**: `pytest tests/test_cp5.py -v`.

## 3. Phân Tích 10 Câu Hỏi Phản Ánh (exercises.md)
Tập tin [exercises.md](file:///d:/tai%20lieu%20hoc%20tap/VinAI/Day12/Lap/K3-Day12-Cloud-Services-And-Deployment/exercises.md) yêu cầu học viên tự đúc kết kinh nghiệm sau quá trình làm lab:
1. **Fail fast**: Ưu điểm của việc chết sớm khi thiếu cấu hình so với việc dùng giá trị mặc định (tránh âm thầm tính phí hoặc chạy sai cấu hình).
2. **Log JSON**: Khả năng phân tích log tự động thông qua máy đọc so với câu lệnh `print` thông thường.
3. **Kích thước image**: Sự chênh lệch dung lượng giữa Dockerfile 1 stage và Multi-stage là do các compiler, cache và library thừa không được mang sang runtime stage.
4. **Caching Layer trong Docker**: Cách hoạt động của cache layer khi thay đổi code và tầm quan trọng của thứ tự copy file.
5. **Non-root User**: Rủi ro bảo mật nếu kẻ tấn công khai thác được ứng dụng chạy quyền root và cách câu lệnh `USER` cô lập tiến trình.
6. **Cửa sổ trượt vs Cửa sổ cố định**: Cách hacker bypass rate limit 10 req/phút của cửa sổ cố định để gửi 20 request trong 2 giây xung quanh mốc reset phút.
7. **Rate Limit vs Cost Guard**: Rate limit giới hạn tần suất request (bảo vệ hạ tầng), Cost guard giới hạn số lượng token tiêu tốn quy đổi ra USD (bảo vệ ví tiền).
8. **Cascading Failure**: Hậu quả nếu gộp `/health` và `/ready` kiểm tra Redis chung khi Redis gặp sự cố (LB sẽ restart sạch cụm container).
9. **Stateless**: Sự khác biệt về lịch sử trò chuyện khi load balancer phân phối request qua lại giữa 3 container khác nhau.
10. **Cloud Debugging**: Cách đọc log cloud để tìm và sửa lỗi khi deploy.
