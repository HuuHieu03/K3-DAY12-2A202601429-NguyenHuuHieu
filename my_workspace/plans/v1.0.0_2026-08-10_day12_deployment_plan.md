# Kế Hoạch Thực Hiện - Day 12 Deployment Lab

## 1. Tổng Quan & Mục Tiêu

Bài lab này dẫn dắt người học từ một AI agent chạy trên localhost đến một dịch vụ production-ready có thể deploy lên cloud. Kế hoạch này chia bài thành các phase rõ ràng để nắm được cả kiến thức nền tảng lẫn thực hành triển khai.

Mục tiêu của kế hoạch:

- Hiểu bản chất khác nhau giữa development và production.
- Nắm được Docker, cloud deployment, security, scaling và reliability.
- Hoàn thành final project ở `06-lab-complete` với đầy đủ checklist production readiness.
- Chuẩn bị được các tài liệu bàn giao như `MISSION_ANSWERS.md`, `DEPLOYMENT.md` và screenshot.

## 2. Phạm Vi & Thay Đổi Kiến Trúc

### Phạm Vi

- Đọc và phân tích toàn bộ tài liệu gốc của day12 lab.
- Thực hiện bài theo từng phần từ Part 0 đến Part 6.
- Theo dõi tiến độ bằng file progress riêng trong `my_workspace/progress/`.
- Ghi lại tổng hợp và tài liệu hỗ trợ trong `my_workspace/docs/`.

### Không Bao Gồm

- Không refactor toàn bộ codebase gốc ngoài phạm vi bài lab.
- Không thay đổi kiến trúc tổng thể của repository bài tập.
- Không xây dựng thêm tính năng ngoài mục tiêu lab nếu không cần cho deliverable.

### Thay Đổi Kiến Trúc Cần Hiểu

- Chuyển từ app đơn lẻ sang app có config từ environment.
- Chuyển từ môi trường local sang containerized runtime.
- Chuyển từ app chạy local sang cloud deployment có public URL.
- Thêm lớp bảo vệ API và kiến trúc stateless để chuẩn bị scale.

## 3. Danh Sách Công Việc

### Phase 0 - Chuẩn Bị Bối Cảnh

- [ ] Đọc `README.md`, `LAB_GUIDE.md`, `DEPLOYMENT.md`.
- [ ] Hiểu cấu trúc tổng thể của 6 phần trong bài lab.
- [ ] Nắm yêu cầu môi trường: Python, Docker, Git và terminal.

Kiến thức cần nắm:

- Day 12 lab muốn giải quyết bài toán gì.
- Tại sao cần học theo trình tự từ local đến production.
- Vai trò của mock LLM và các tài liệu hỗ trợ.

### Phase 1 - Localhost vs Production

- [ ] Đọc `01-localhost-vs-production/develop/app.py` để tìm anti-patterns.
- [ ] Chạy bản basic để quan sát hành vi thật.
- [ ] So sánh với bản `production/` để hiểu env vars, health check và graceful shutdown.

Kiến thức cần nắm:

- Hardcoded secrets và config trong code là rủi ro gì.
- Vì sao health check và graceful shutdown quan trọng.
- Khái niệm 12-factor app và dev/prod parity.

### Phase 2 - Docker Containerization

- [ ] Đọc Dockerfile basic ở `02-docker/develop`.
- [ ] Build và run image basic.
- [ ] So sánh với bản `02-docker/production` để hiểu multi-stage build và compose stack.

Kiến thức cần nắm:

- Docker image, container, layer và port mapping.
- Vì sao nên copy `requirements.txt` trước source code.
- `.dockerignore` giúp giảm kích thước và tránh leak gì.
- Multi-stage build tối ưu image như thế nào.

### Phase 3 - Cloud Deployment

- [ ] Đọc cấu trúc `03-cloud-deployment/`.
- [ ] Chọn platform theo mục tiêu học tập: Railway, Render hoặc Cloud Run.
- [ ] Hiểu cách set env vars và nhận public URL từ platform.

Kiến thức cần nắm:

- Khác nhau giữa MVP deployment và production deployment.
- Cold start là gì và ảnh hưởng UX ra sao.
- Khi nào nên đi từ Railway/Render lên Cloud Run.

### Phase 4 - API Gateway & Security

- [ ] Chạy bản basic trong `04-api-gateway/develop`.
- [ ] Test API key authentication.
- [ ] Đọc bản production để hiểu JWT, rate limiting và cost guard.

Kiến thức cần nắm:

- API Key, JWT và mục đích của từng loại.
- Vì sao phải chặn request đầu vào trước khi gọi agent.
- Rate limiting bảo vệ hệ thống và ngân sách như thế nào.
- Cost guard giúp kiểm soát chi phí AI ra sao.

### Phase 5 - Scaling & Reliability

- [ ] Chạy phần health check và graceful shutdown trong `05-scaling-reliability/develop`.
- [ ] Hiểu cơ chế readiness/liveness probe.
- [ ] Chạy bản production với Redis và Nginx để kiểm tra stateless design.

Kiến thức cần nắm:

- Liveness vs readiness khác nhau thế nào.
- Stateless design vì sao cần thiết khi scale ngang.
- Redis dùng để chia sẻ session giữa nhiều instance như thế nào.
- Nginx/load balancer đóng vai trò gì trong kiến trúc production.

### Phase 6 - Final Project

- [ ] Hoàn thành `06-lab-complete` theo checklist.
- [ ] Kiểm tra Dockerfile, docker-compose, config, security và shutdown.
- [ ] Chuẩn bị deliverables cuối cùng cho bài nộp.

Kiến thức cần nắm:

- Tại sao final project phải tích hợp đủ các khối kiến thức trước đó.
- Những tiêu chí nào chứng minh hệ thống đã production-ready.
- Các đầu ra cần nộp theo delivery checklist.

## 4. Phương Án Kiểm Thử

### Kiểm Thử Theo Phase

- Phase 1: gọi `/ask`, kiểm tra `/health`, đối chiếu behavior basic và production.
- Phase 2: build Docker image, chạy container, kiểm tra port mapping và compose stack.
- Phase 3: deploy lên cloud, xác nhận public URL và env vars hoạt động.
- Phase 4: test request không key, có key, vượt rate limit và trường hợp hết budget.
- Phase 5: test graceful shutdown, readiness probe và stateless session qua nhiều instance.
- Phase 6: chạy production readiness checker và đối chiếu checklist bàn giao.

### Tiêu Chí Đạt

- Mỗi phase phải chạy được tối thiểu một kiểm thử xác nhận.
- Không còn hardcoded secrets trong các phần đã chỉnh sửa.
- Final project phải đáp ứng các yêu cầu chính: auth, rate limit, cost guard, health checks, graceful shutdown, stateless design và deploy được.
