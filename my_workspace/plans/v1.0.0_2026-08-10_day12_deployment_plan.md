## 2. Kế Hoạch Các Bước Thực Hiện Chi Tiết

### Phase 0 — Setup Môi Trường & Checkpoint 0
- [ ] Thiết lập môi trường ảo Python 3.11+.
- [ ] Chạy `pip install -r requirements.txt`.
- [ ] Tạo file `.env` từ `.env.example`, sinh và thiết lập `AGENT_API_KEY`.
- [ ] Khởi động Redis bằng Docker Compose: `docker compose up -d redis`. Nếu chưa có Docker, đặt `REDIS_URL=fake://` trong `.env`.
- [ ] Chạy test CP0: `pytest tests/ -v -m "not docker"`.

### Phase 1 — 12-Factor Config, Health & Logging (CP1)
- [ ] **Config (`app/config.py`)**: Khai báo các thuộc tính trong `Settings` sử dụng `pydantic-settings`. Chú ý `agent_api_key` **không được có giá trị mặc định**.
- [ ] **Logging (`app/logging_utils.py`)**: Hoàn thiện hàm `log_event` để log ra một dòng JSON duy nhất trên stdout sử dụng `json.dumps(..., ensure_ascii=False)`.
- [ ] **Health check (`app/main.py`)**: Tạo endpoint `/health` trả về HTTP 200 `{"status": "ok"}` (hoặc 503 nếu app đang tắt). Endpoint này **không** gọi dependency bên ngoài (Redis, DB).
- [ ] Chạy test CP1: `pytest tests/test_cp1.py -v`.

### Phase 2 — Docker Containerization (CP2)
- [ ] **Dockerfile**: 
  - Sử dụng multi-stage build (`AS builder` và `AS runtime`) để tối ưu dung lượng image < 500MB.
  - Tận dụng cache bằng cách copy `requirements.txt` và cài đặt trước khi copy thư mục `app/`.
  - Tạo và chạy dưới quyền `appuser` (non-root, uid 10001).
  - Thêm lệnh `HEALTHCHECK` kiểm tra `/health`.
  - Chạy `uvicorn` bind vào `0.0.0.0:${PORT:-8000}`.
- [ ] **.dockerignore**: Loại bỏ `.env`, `.git`, `__pycache__`, `.venv` khỏi build context.
- [ ] **docker-compose.yml**: Khai báo service `agent` phụ thuộc vào `redis` (`depends_on`). Truyền biến môi trường `AGENT_API_KEY` từ `.env` và `REDIS_URL=redis://redis:6379/0`.
- [ ] Chạy test CP2: `pytest tests/test_cp2.py -v`.

### Phase 3 — API Security (CP3)
- [ ] **Authentication (`app/auth.py`)**: Xác thực request qua header `X-API-Key`. Sử dụng `secrets.compare_digest` để so sánh an toàn thời gian. Trả về `user_id` từ header `X-User-Id` (mặc định `ANONYMOUS_USER`).
- [ ] **Rate Limiting (`app/rate_limiter.py`)**: Dùng Redis Sorted Set để triển khai sliding window 60 giây. Key theo user: `rate_limit:<user_id>`. Lưu ý: kiểm tra số lượng request trong cửa sổ trước khi add request hiện tại để tránh chặn nhầm. Member ZSET phải là duy nhất (`f"{timestamp}:{uuid}"`).
- [ ] **Cost Guard (`app/cost_guard.py`)**: Tính toán chi phí USD của LLM response và lưu/cập nhật vào Redis với key định dạng `cost:<user_id>:<YYYY-MM>`. Chặn request (403) nếu vượt quá `MONTHLY_BUDGET_USD`.
- [ ] Chạy test CP3: `pytest tests/test_cp3.py -v`.

### Phase 4 — Scaling & Reliability (CP4)
- [ ] **Stateless Session Store (`app/store.py`)**: Lưu lịch sử chat vào Redis dạng list (`rpush`). Sử dụng `ltrim` để giới hạn số lượng message (`HISTORY_MAX_MESSAGES`) và `expire` để dọn dẹp hội thoại cũ. Hàm `ping()` phải nuốt exception và trả về `False` khi Redis chết.
- [ ] **Readiness Probe (`/ready`)**: endpoint `/ready` trả về 200 khi Redis kết nối được, ngược lại trả về 503 (không restart container).
- [ ] **Graceful Shutdown (`app/lifecycle.py`)**: Bắt tín hiệu `SIGTERM` và `SIGINT`. Khi nhận tín hiệu, set flag `shutting_down = True` (khiến `/health` và `/ready` trả về 503 để load balancer rút instance ra), và nhường lại việc shutdown cho uvicorn.
- [ ] Chạy test CP4: `pytest tests/test_cp4.py -v`.

### Phase 5 — Cloud Deployment (CP5)

- [ ] Tạo dịch vụ Redis và liên kết `REDIS_URL` tới FastAPI Web Service.
- [ ] Cấu hình các biến môi trường trên dashboard (không commit file `.env`).
- [ ] Điền thông tin deploy thực tế (Public URL, platform, kết quả curl test) vào [DEPLOYMENT.md](file:///d:/tai%20lieu%20hoc%20tap/VinAI/Day12/Lap/K3-Day12-Cloud-Services-And-Deployment/DEPLOYMENT.md).
